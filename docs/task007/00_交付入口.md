重启后的实时会话不会留在内存里。`POST /v1/fusion/replay` 只在临时会话重建历史，不恢复原来的 `sessionId`。继续实时融合时新建会话并重新发送 `POST /v1/fusion/process`。

没有 `scanId` 的观测，按同一 `detectorId` 的 50 毫秒桶竞争。有 `scanId` 的同一次扫描先整组一对一预留，再按测量时间更新滤波，输入顺序不改变目标归属，也不把滤波时钟拨回。扫描释放后，`closed_scan_reject_s`（4 秒）内同一扫描上的另一个设备局部编号返回 `scan_closed`，不并入已有目标。同一局部编号可以继续。超过该窗口后扫描号可以复用。算法生成的局部编号不是设备身份。

可信 `aircraftId` 在波门内且只有一条同号航迹时，保持该航迹，不因为旁边有更近的匿名航迹而改挂。越出波门的同号不抄到匿名航迹上。多条同号航迹同时在波门内时给出 `identity_ambiguous`。

单批 `trajectoryUpdates` 返回本批全部已提交点。`committedHistory` 最多保留 80 点。公开 `POST /v1/fusion/process` 在 realtime 与 replay 两种 mode 下都保留幂等重试与冲突语义；达到 `max_idempotency_ids` 后新 batch 返回 `idempotency_capacity`。仅内部临时 `replay_job` 逐帧不占用该名额。回放业务失败返回非 2xx。摘要区分 `input`、`valid`、`processed`、`rejected`、`unprocessed`；中止时不写已全部处理。

同一次扫描若因末点仍在重排窗内被整体持有，测量时间落在该扫描时间跨度内的其他设备观测一并等待，避免更晚事件先更新滤波后把更早匿名点吃掉。扫描预留包含尚未生成目标的逻辑槽位，交错设备可先填入同一槽位。

逻辑槽位与真实航迹使用同一套身份、航向与时刻门。同一扫描内多个同 SN 强制行争用一列时给出明确歧义，不二次占用。重叠持有跨度按扫描整组传递等待，不拆开同扫成员。

待生成槽位的测量时刻只作参考锚点；与已提交 KF 状态时刻分开。跨设备较早观测匹配未来槽位时，在同一时刻比较位置/运动，不按迟到门排除。真实航迹仍保留负 dt 保护。
