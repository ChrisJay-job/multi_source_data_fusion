# 历史保留 / 查询范围与资源边界（Round3）

## 现行行为

- 引擎在每条 Track 上保留完整 `committed_updates`（主 KF 提交点）；快照字段 `committedHistory` 为该列表副本。
- 每帧 runner 响应携带当时活跃 tracks 的完整提交历史；前端按 `snapshots[0..tIndex]` 归档最长历史绘制，倒退播放按 `nowT` 截断未来点；目标终止后仍可画已提交实线。
- 预测历史按预测 episode（进入/退出 `predicted`）分段，不跨实测恢复串线。

## 范围与限制

| 项 | 说明 |
|---|---|
| 保留范围 | 单次工作台 run 会话内；不跨 session 持久化轨迹库 |
| 查询 | 前端按播放时刻过滤；无服务端分页/增量索引 |
| 小规模验证 | 七机 ~40s、单机多次停源 55s：pytest + Node 探针 + Playwright 两视口 |
| 未测 | 约 2GB 全量 SQL 导入下的完整历史携带与内存峰值 → **NOT_TESTED** |
| 不宣称 | 当前路径已适合大文件完整历史回放 |

若后续做增量索引/缓存，须回归：倒退无未来点、终止后提交历史仍在、预测 episode 不跨实测。
