## 4. 场景交付

保留 seven_aircraft_combinations 原预置与行为。新增“七机＋挑战组”预置，保留 A–G 并新增 H–M 六架：H/I 同时交叉、J/K 2m 平行、L/M 同向追越。各组放在相互隔离的区域，避免跨组门控干扰；页面提供一键聚焦组内与适应全图。2m 组必须可局部放大、显示米制标尺与真值最近距离。

同时提供每组可单独运行的预置，便于定位问题。每个场景导出：轨迹、起飞偏移、速度、来源、身份可用性、噪声、延迟及种子；导出重导后可复现。

| 场景 | 必须构造的条件 | 主要检查 |
|---|---|---|
| 同时交叉 | 两机在明确时刻到达交点；至少一个匿名雷达源；交叉前后均保留观测 | 串轨、ID交换、错误合并、恢复 |
| 错时交叉 | 几何交点相同但到达时间不同 | 不能只按几何交点判断冲突 |
| 近距平行 | 2m、5m、10m、30m、100m 距离档位，同向同速 | 随间距及噪声变化的误关联、歧义和漏关联 |
| 同向追越 | 后机速度更大，航段及运行时间确保发生追越 | 最近邻交换及持续性 |
| 交叉时来源中断 | 在交叉邻域让一机 RID 短暂停报，保留其他来源 | 主源退化、接续、错误吸附 |
| 交叉时局部号更换 | 雷达局部号改变，标识值不携带可用真值含义 | 是否依赖命名规律；错误接续 |

每个核心挑战提供“可靠不同身份”和“缺少可靠身份”两种配置；身份能力应按来源独立配置，可让 RID 有 SN 而频谱无 SN。保留兼容旧场景的默认值。匿名仍需有效的设备号和局部航迹号，但不伪造可信 aircraftId。

真值、飞机标签、预期 fusionId 不得进入算法或参与关联。局部 ID 使用不透明值；增加重命名、输入顺序扰动测试，证明不依赖 A/B 或后缀规律。

对所有核心挑战至少运行 5 个固定种子，不用单个幸运种子宣称鲁棒。场景构造应解析或计算验证：是否真的同时交叉、最小间距、追越时刻，禁止仅凭命名认为挑战存在。

## 5. 页面必须让用户读懂

### 5.1 图层和默认显示

默认突出融合提交历史＋当前位置，真值可辅助对照；原始三源和预测历史按需展开，避免全图默认叠满同色轨迹。提供“简洁看结果”“原始观测对比”“关联排查”三种快捷显示组合，用户仍可单独勾选图层。

图例用完整中文，给出颜色、线型、数据出处和含义：计划航线（当前实现若实际使用真值折线，必须如实标记或改为真正 waypoint 计划线）、真值已飞轨迹、RID/频谱/雷达观测连线、融合提交历史、当前估计、预测历史、方向示意。说明观测连线只是时间顺序连接的离散观测，不是额外实测；预测不是新测量；提交历史也不是精度已验证的真实轨迹。

### 5.2 目标分组与结果

按飞机/融合目标组织筛选项；把 A、SN、fusionId、局部源 ID 放在同一目标的详情里，避免并列成大量难懂复选项。无真值的真实数据按融合目标及来源组织，不伪造飞机映射。

点击目标显示：来源清单及最近观测时间、活跃/历史绑定区别、主位置来源、trackStatus、positionMode、fusionId、身份可用性、最近更新与时间差。支持定位到疑似错误的时间段与观测。

### 5.3 “为什么这样关联”

展示已有算法响应/事件能支撑的信息：观测标识、来源、候选或最终目标、已输出的门控/歧义/拒绝原因、当前主位置来源。若现有接口未暴露候选距离或代价，应显示“当前未输出”，不能在前端重新推测后当成算法内部证据。需要新增引擎诊断时仅列为后续建议，本轮不改冻结引擎。

### 5.4 时钟和计数

用易懂名称并列展示“页面播放时间 processingTime”“已提交事件水位 watermark”“最后实测时间”。例如 realtime 重排窗口 2s 时，当前点预测至页面时刻并不表示漏接或误关联。

分开统计观测接收数、已处理数、主位置更新数、仅绑定数、缓冲数、拒绝数。不得把不同计数直接比较并解释成漏数据。
