## 二、必须修复的缺陷

### R01 实时水位和状态推进错误：P0

位置：`engine.py: process / _advance_lifecycle / _update_track`。

配置重排窗 2 秒，连续在 processingTime=1…6 秒各报一条同目标观测。第 3 秒才处理 t=1，却立即把主状态预测到 t=3；后续 t=2、t=3 等正常出缓冲观测被当作 stale 忽略。第 6 秒 lastObservedAt 仍为 t=1。watermark 还曾从 t=2 倒退到 t=1。

整改：提交状态以单调事件水位推进，生命周期按有效事件时间判断；若要展示处理时刻预测，使用不污染可更新状态的预测副本。确保窗口内观测正常更新、窗口外旧观测明确拒绝、空批推进不跳过尚未成熟数据。不得靠关闭实时缓冲或把全部运行改成 replay 绕过。

### R02 雷达先出现，RID 后出现不能补身份：P0

位置：`_associate` 的 RID／频谱带 SN 分支直接 return None。

复现：雷达 t=1 建轨，RID t=1.4 出现在相距约 9 米处，结果为独立 radar 和 rid 两目标，无归并事件。原 T03 最后允许“原雷达仍存在”即通过，掩盖了失败。

整改：可信身份观测应能匹配无身份目标；在唯一、物理合理且有足够支持的情况下补身份，保留最早可靠发布 ID；确认规则若需要多帧，补足多帧后断言收敛为单实体。回归中的唯一近距简单场景应可直接关联；如果采用多帧保守策略，可调整输入长度，不能放宽最终断言。

### R03 RID 优先只有标签，未控制滤波更新：P0

位置：`_update_track` 在选择来源前对每条观测无条件 `kf.update`。

复现：同一时刻 RID 经度 117.2，雷达偏移约 43 米，输出经度被拉到 117.20004545454547，但 positionSource 仍为 rid。

整改：先决定来源，非主来源不直接更新主位置 KF；保留绑定、身份、质量和后备作用。同一时刻多源批必须统一决策，消除顺序差异。新增来源输入不能用标签掩盖坐标混合。

### R04 身份拒绝后仍可无条件归并／旧绑定绕过冲突：P0

位置：`_associate`、`_maybe_merge`。

复现：RID SN-A 后，频谱同 SN 在约 8.6km 外出现，先产生 identity_physics_reject，随后仍 track_born＋alias_merge，两个来源又被归到同一目标。另一个复现中，频谱原航迹键不变、payload SN 从 A 变 B，仍更新 A 并仅记录 identity_mismatch。

整改：归并必须复用身份和时空门控；拒绝的候选不能从另一入口强并。不同可信 SN 硬冲突应先阻止位置更新并进入异常／解绑流程。雷达旧键复用也必须再次门控，不能永久无条件绑定。

### R05 全局分配没有实现：P0

`linear_sum_assignment` 仅 import，没有调用。当前逐条最近目标选择不等于按设备微批的全局分配；未实现创新马氏距离门控，confirm_hits 也未生效。

整改：对事件时间微批按设备构建候选代价矩阵，预测至比较时刻，先门控、加入显式未匹配代价、全局分配，再执行绑定确认。不同设备可匹配同一目标，同设备同轮一对一；观察顺序不应决定归属。保持现有 KF／CPU 方向，不引入 JPDA／MHT／IMM。

### R06 幂等及回滚不成立：P0

- 去重表 seen_ids 仅在单次请求内，重复 observationId 换 batchId 后重复更新，同一观测三次即可把 tentative 升为 tracked。
- batch hash 只含 observations，processingTime 和 mode 改变仍返回旧缓存；session 未锁定 mode。
- 第二条 ingest 注入异常时返回 batch_rollback，但第一条目标仍在，next_id 已增长，缓冲已被取走，未恢复。
- 事件没有稳定 eventId；API 冲突返回 HTTP 200。
- FastAPI 同步路由在线程池调用共享状态，无 session 锁；单 worker 不等于同 session 串行。

整改：规范化完整请求指纹、跨批观测去重与内容冲突检查、session 模式固定、同 session 锁和独立 session 隔离、事务式提交／恢复、稳定事件 ID、规范 HTTP 状态。业务冲突 409；逐条坏观测仍可随合法观测返回 200；异常失败不残留半批状态。

### R07 标准接口和映射边界错误：P0

标准 Observation 使用 measurementTime／detectorId／sourceTrackId，当前 normalize_row 只读原表 created_at／detector／id，标准观测返回 missing_time。实际 API 被绑定成了原表接口。

整改：将历史原表适配器与标准核心接口分开；标准观测直接做规范校验，历史 raw 先映射成标准观测，二者共享同一个核心，避免两次反复猜测映射。同步生成完整 OpenAPI、正反样例及真实 HTTP 测试。

### R08 数据质量降级未真正执行：P1，本轮必修

- 经度 181 被接受，未验证经纬度范围和有限数。
- 频谱 heading=az 的有效数值直接作为航向，只有解析失败时才添加提示，与文档“保守降级”不符。

整改：有限数／范围检查；未确认频谱航向置 null＋flag；时区显式配置并保留假设标记，标准 API 的无时区时间拒绝。来源时区未确认的历史回放可使用明确假设档，不声称是真实时钟对齐。未确认 SN 语义不得默认可信。未知高度保留原值／基准标志，仅做水平融合，不猜 -2 语义。

### R09 来源时效、容量和状态未闭环：P1，本轮必修

整改：sources 只输出有效确认来源，历史关系单独保留；来源有效期、状态 TTL、缓存过期／容量和请求上限真正生效；过期批次明确拒绝，不复用为新批。/ready 验证配置与状态拥有者就绪。小规模实现即可，不新增分布式缓存。
