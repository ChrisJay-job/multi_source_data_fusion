## 2. 已确认范围与事实边界

本期必须包含 RID、频谱、雷达。ADS-B、光电、射频指纹、欺骗定性、雷达引导光电不在本轮。

- RID 和频谱具有相同、已确认语义的真实飞行器 SN 时，以身份为主要依据，同时检查时间与位置合理性。
- 雷达编号为设备内部航迹号，不是飞行器 SN；根据时间、位置、速度及运动连续性关联。
- 雷达独立发现目标时建立融合 ID；以后关联上 RID／频谱，补身份并尽量保持已发布 ID，输出归并映射。
- 雷达丢失后换号重现时尝试续接；候选不唯一或证据不足时允许新建，不强接。
- 确认同目标后，有效及时 RID 优先作为位置主来源；不是把附近雷达都并入 RID。
- 短时全部失联时有限预测，明确标 predicted；到期停止外推；重现后可靠匹配再续接。
- 多目标交叉不得只凭最近距离合并；允许保守未匹配和临时目标。

## 4. 阶段 B：最小规格与实现

### 4.1 数据契约

统一观测至少包含：

`observationId, source, detectorId, sourceTrackId, aircraftId, measurementTime, receivedAt, timeBasis, longitude, latitude, altitude, altitudeDatum, speed, heading, verticalSpeed, qualityFlags`。

- 三个 ID 分层：真实飞行器身份、设备内来源航迹、系统融合 ID；来源键至少包含 source＋detectorId＋sourceTrackId，考虑设备重启复用。
- 时间采用带时区 ISO8601；数值为米、秒、米每秒、度。空值为 null，不用 0 冒充未知。
- heading 若有效，定义为真北 0 度顺时针的运动方向；测向方位不能代用。
- aircraftId 仅在语义可靠时填写，雷达无真实 SN 时为 null。
- 历史观测 ID 可用原始文件标识＋表／主键／记录位置稳定生成，不能只用设备＋秒去重。
- 精确重复、ID 冲突、缺关键位置／时间／设备键分别处理；非关键属性缺失不使整条位置观测失效。保留原始行引用和拒绝原因。

接口至少提供：`GET /health`、`GET /ready`、`POST /v1/fusion/process`。

process 请求包含 sessionId、batchId、mode（realtime／replay）、processingTime、observations；允许空批推进。响应返回完整活动快照、拒绝条目与事件，包含 epoch、snapshotSeq、算法／配置版本和 watermark。

目标至少输出 fusionId、trackSegmentId、aircraftId、位置与可用运动量、stateTime、lastObservedAt、trackStatus、positionMode、positionSource、sources、sourceTracks、qualityFlags。未知属性保持 null；不输出伪造的概率置信度。

记录 OpenAPI 和有效／无效 JSON 样例，错误码及边界行为必须与代码一致；逐条观测错误不能一律使整批有效观测失败。

### 4.2 融合核心

1. 固定场景原点，将经纬度转换为经验证的米制水平坐标；未知高度不作为椭球高直接代入三维转换。
2. 用常速度 KF 维护水平位置与速度，按真实 dt 预测，协方差稳定更新。噪声参数全部配置化，标明未标定状态。
3. 已确认同 SN 的 RID／频谱先做身份锚定，同时做物理合理性检查；不同可信 SN 不自动合并。
4. 雷达候选先做时差、距离及创新门控，再按设备分别做全局最小代价分配，允许显式未匹配。不同来源可关联同一融合目标，不能把三源全放入一个一对一矩阵互相排斥。
5. 最优／次优过于接近时保留歧义；重复消息不累计连续支持次数。候选确认计数与观测周期有关，不与 HTTP 调用次数绑定。
6. 每次位置更新选择一个有效主来源，有效及时 RID 优先，其余来源保留绑定及后备作用。首版不是统计最优的多源加权融合，不盲目平均已滤波航迹。
7. 实现 tentative／tracked／coasting／lost／terminated 的明确生命周期，以及 measured_assisted／predicted／stale 等位置状态。预测不能刷新 lastObservedAt。
8. 实现雷达换号的有界重关联、身份后补、受控重复目标归并与 alias 事件。归并固定保留规则，避免已发布 ID 反复跳变。
9. 跳点拒绝，持续矛盾时解除具体来源绑定并重新分配；不实现复杂历史自动拆分和报表追溯修复，但必须记录冲突／解绑事件。

### 4.3 状态与可靠性最低要求

- 单进程持有状态，每 session 串行处理，测试不同 session 不串数据；不得默认开启多个独立状态 worker。
- 有界乱序缓冲，按测量时间处理，旧观测不倒写状态；空批推进水位。replay 使用虚拟时钟。
- 相同 batchId＋相同内容重试返回同一结果、序号和事件；同 ID 不同内容返回冲突。
- 批处理状态及幂等结果原子提交，异常不残留半批状态；先查缓存再检查处理时间单调性。
- 缓存、会话、来源映射和结束轨迹有 TTL／容量限制，过期重试不得当新数据重新融合；明确返回错误。
- 重启生成新 epoch，ID 不碰撞；跨进程重启沿用原 ID 暂缓，写清调用方清理旧快照的规则。
